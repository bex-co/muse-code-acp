## Objective

When a 1.4.14 host serves an `earlierHistory` item in place of a compacted session's pruned prefix, replay shows its user/assistant tail messages as history, not a generic card.

## Context

- `EarlierHistory.messages`: at most 50 `{role, text}` entries, with roles `user`/`assistant` (skip others), text at most 1,000 characters. `turnId` is always null. The host derives it from the boundary checkpoint (ADR 71910).
- Not observed in the 2026-10-28 R4 replay on 1.4.14, so the producing condition must be found first (likely a long compacted session or a paged `view/page` read).
- Replay must keep message boundaries (`messageId`), as w3/m20 t003 established.

## Steps

1. Find when the host emits it: a real-provider compacted session read with `session/read` / `view/page`.
2. Map each message to `user_message_chunk` / `agent_message_chunk`, each with its own `messageId`, in tail order; skip unknown roles.
3. Add a `fake-msp.cjs` mode that serves an `earlierHistory` item and a unit test of the replay.

## Closed by triage

The objective (history shown, no generic placeholder card) already holds without new code:

- `earlierHistory` always has `turnId: null`. Live turns stream only items of the active turn: `turn.items()` and `flushFold` filter on `held.turnId === turn.turnId` (`src/muse-sdk.ts`). Restored cards are only unfinished workers and tools (`restoredTaskUpdates`). So the item never reaches an ACP client.
- `session/load` replays from `muse export` (`runMuseExport` in `src/session-lifecycle.ts`), not from SDK items. On 1.4.14 the replay of a compacted session still contains the pre-compaction prompts (`/qa-find-bugs` R4 restore, 2026-10-28).
- The classification entry in `src/muse-view-events.ts` records this, as does `docs/sdk-migration.md`. No fake-msp mode was added because no code path consumes the item.
