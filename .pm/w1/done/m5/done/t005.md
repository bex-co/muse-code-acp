## Objective

Use the SDK's gap-fill contract to repair dropped delivery while preserving the ACP transcript and avoiding repeated model or tool execution.

## Context

- The installed SDK Session layer provides view/page splice-fill and onGapError; the adapter currently treats every view/gap as a terminal failure.
- SDK gap recovery restores item state rather than the exact lost delta sequence. ACP text is append-only, so reconciliation must use already-emitted content carefully.

## Steps

1. Connect ACP translation to SDK gap recovery and hold publication while the SDK's current view is incomplete.
2. Extend the fake MSP host with a recoverable gap, paged overlap, held live events, page failure, and non-advancing/repeated cursors.
3. Emit only previously unseen text suffixes and item revisions once the fold is current; treat irreconcilable text/state as a visible recovery error instead of guessing.
4. Route failed/stalled fills through an explicit prompt failure and reload/recovery instruction, with no automatic turn resubmission.

## Acceptance criteria

- [ ] A recoverable gap produces the complete ordered visible answer and tool state exactly once, including final-state-only text from the fill.
- [ ] The MSP transcript contains no extra turn/start or duplicate protected execution during delivery recovery.
- [ ] Repeated cursors, stalled pages, and page errors fail deterministically instead of hanging or reporting partial state as complete.
- [ ] A failed recovery clears adapter turn state and permits a documented subsequent load/prompt path.

## Out of scope

- Reimplementing SDK splice-fill, inventing snapshot re-anchor APIs, and replaying ambiguous side effects.
