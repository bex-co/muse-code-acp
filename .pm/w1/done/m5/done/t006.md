## Objective

Ensure backend and client failures produce accurate ACP outcomes without leaking execution state into later turns or hanging teardown.

## Context

- Current SDK tests cover several startup and terminal failures but not all races across client callbacks, active tools, and session generations.
- Reference auth-error-events.test.ts and process-exit-error.test.ts separate current-turn failures from foreign events and capture subprocess failures.

## Steps

1. Script launch failure, authentication failure, step limit, malformed MSP, EOF, nonzero exit, and a host that ignores normal shutdown.
2. Add current/foreign turn failures both before and after acceptance, and client disconnect while permissions or delivery are pending.
3. Preserve typed ACP error categories and actionable sanitized diagnostics; do not report a host exit as successful model completion.
4. Assert disposal of listeners, pending callbacks, timers, active-turn state, hosts, and settings overlays; verify a fresh turn/session after failure.

## Acceptance criteria

- [ ] Every scripted terminal path settles the ACP request once with the documented error or stop reason.
- [ ] Foreign and stale events cannot fail or complete another active turn, including before its acknowledgement.
- [ ] Client-facing diagnostics contain useful failure context without fixture credentials or raw secret-bearing settings.
- [ ] Teardown completes within a bounded deadline even for an unresponsive child, and required temporary resources are released.
- [ ] No failure path silently falls back to exec or repeats a possibly accepted command.

## Out of scope

- Broad security auditing, provider-specific retry systems, and automatic recovery through a different backend.
