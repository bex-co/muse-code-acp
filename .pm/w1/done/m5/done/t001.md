## Objective

Replace the SDK approval failure path with a genuine client decision round trip so editor users control the exact protected tool call.

## Context

- The agent client seam currently exposes only sessionUpdate, and SDK approval/requested throws.
- The SDK exposes Session.onApproval and typed approval decisions; available choice IDs come from the host. Reference approval-events.test.ts asserts both request details and backend decisions.

## Steps

1. Extend the ACP client seam with permission requests and register the SDK approval handler before a turn can emit approval events.
2. Translate tool identity, pending status, command/path arguments, and only available host choices into ACP permission options.
3. Map selected options back to the exact host decision and preserve denial versus cancellation wherever the protocol distinguishes them.
4. Add fake-MSP and ACP wire tests proving the backend remains waiting until a valid client response arrives.

## Acceptance criteria

- [ ] Allow and deny produce the matching host-offered decision and the ACP tool status/output follows the actual result.
- [ ] The tool cannot execute before the client response; no default grant or fabricated choice is sent.
- [ ] Client cancellation, invalid option IDs, and missing responders resolve through a documented non-granting path.
- [ ] Permission request metadata and result correlation survive actual ACP serialization.

## Out of scope

- Fabricated approval scopes, interactive permissions for legacy exec, and default safety bypass flags.
