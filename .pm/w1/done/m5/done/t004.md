## Objective

Make ACP cancellation terminate the intended execution at every asynchronous boundary and leave the session ready for its next prompt.

## Context

- Existing SDK tests cover cancellation during startup and an active turn; approvals and elicitation introduce additional waiting states.
- The reference session-close.test.ts catches delayed starts and stale resumed generations. Reuse the race patterns without adding an optional session/close endpoint.

## Steps

1. Add controlled barriers for handshake, session opening, turn acceptance, text streaming, tool execution, and pending permission/input.
2. Issue session/cancel at each barrier, including repeated cancellation and completion racing with cancellation.
3. Assert bounded SDK cancellation/teardown, one ACP settlement, and the ordering of any final updates before the cancelled prompt response.
4. Test a second prompt on the same session, two independent sessions, and the current rejection policy for overlapping prompts on one session.

## Acceptance criteria

- [ ] Each cancellation scenario resolves the active ACP prompt once with stopReason cancelled within a bounded test deadline.
- [ ] No late turn/start is submitted after cancellation during startup; a cancelled tool cannot be unblocked by a late approval.
- [ ] Updates emitted while cancelling precede the prompt response; no stale turn update leaks into the next prompt.
- [ ] The next prompt succeeds and cancellation in one session does not terminate another.

## Out of scope

- Steering/queued-prompt extensions, optional session-close APIs, and fixed sleeps used as race synchronization.
