## Objective

Prove that MSP events produce the ACP transcript an editor needs, including tool lifecycle details and output that arrives only at completion.

## Context

- src/muse-sdk-events.ts currently handles agent messages and tool calls using presentResult from src/tool-calls.ts.
- Reference tests cover agent messages, file changes, terminal output, reasoning, plans, and usage; implement only event families Muse actually exposes and the adapter promises.

## Steps

1. Build a small typed MSP fixture corpus for text deltas, final snapshots, tool start/update/completion, failures, and interleaved calls.
2. Assert stable IDs and kinds, raw arguments, normalized output, absolute file locations, add/edit/delete/rename diffs, and terminal-style output where Muse supplies them.
3. Cover completion without start, repeated/older revisions, accumulated text after deltas, and slow client delivery so updates remain ordered before the prompt response.
4. Record the policy for optional reasoning/plan/usage events; test emitted mappings if supported and explicit capability absence otherwise, without fabricating encrypted reasoning.

## Acceptance criteria

- [ ] Every advertised event family has explicit semantic assertions at the ACP boundary, beyond a large snapshot.
- [ ] Deltas plus final snapshots produce each visible text segment once; completion-only events remain visible.
- [ ] Concurrent tool calls retain their own inputs, outputs, status transitions, and locations.
- [ ] Late/duplicate events do not create duplicate tool execution or updates for a different turn.

## Out of scope

- Reimplementing SDK folding, client terminal RPC delegation, invented reasoning, and Codex-only event families.
