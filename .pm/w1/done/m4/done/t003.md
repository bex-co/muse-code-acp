## Objective

Replace duplicated MSP lifecycle bookkeeping with the SDK's public session and turn facilities while keeping the current per-turn host ownership model small and reviewable.

## Context

- spawnMuseSdkTurn currently owns command IDs, notification filtering, terminal settlement, and a partial item map.
- Use MuseClient/Session when they cover the operation; compose public Connection and spawn APIs only where the facade lacks required controls.

## Steps

1. Refactor session start/resume and turn submission to public typed SDK facilities, retaining the adapter's ACP handle seam.
2. Attach event consumers early enough to preserve pre-ack/completion-only output and use negotiated durability rather than assuming a host profile.
3. Preserve UUIDv7 creation, legacy session IDs, workspace checks, missing-session-only creation, and existing MCP environment overlays.
4. Bound startup and close behavior and verify that aborted startup cannot submit a late turn; extend the existing tests instead of recreating them.

## Acceptance criteria

- [ ] Start, resume, pre-ack completion, and cancellation during handshake pass through the public SDK APIs.
- [ ] Busy/corrupt/wrong-workspace sessions fail without creating a replacement session or repeating a prompt.
- [ ] The SDK owns MSP framing, IDs/retry correlation, and fold routing; adapter code owns ACP translation and user-facing error semantics.
- [ ] Normal completion and failure both close the host and remove the per-turn overlay.

## Out of scope

- Persistent host pooling, automatic replay of ambiguous side effects, and default cutover.
