## Objective

Make initialization and failure responses accurately describe what this backend and client can execute, preventing SDK migration from advertising unusable protocol features.

## Context

- initialize currently uses Math.min for protocol selection and returns authMethods without client-capability filtering.
- ACP v1 requires supported version negotiation and treats omitted client capabilities as unsupported; custom extension fields are not baseline requirements.

## Steps

1. Add wire tests for supported, older unsupported, and newer unsupported requested versions; implement the specification's selection rule.
2. Exercise absent, empty, and supported client capability combinations, including terminal-auth eligibility and unsupported filesystem/terminal/elicitation calls.
3. Verify invalid params, unknown methods/sessions, auth-required errors, internal errors, and supported metadata survive serialization with the expected IDs.
4. Tie every advertised optional capability to a contract test; validate initialization-before-session behavior and report unsupported content consistently.

## Acceptance criteria

- [ ] Negotiation never returns a protocol version the adapter does not support.
- [ ] Missing client capabilities never cause the adapter to invoke an unavailable client method.
- [ ] Every advertised feature has a passing contract, and invalid requests preserve the correct JSON-RPC error category over stdio.
- [ ] Custom metadata round trips without importing Codex/AIR-specific error types.

## Out of scope

- Claiming support for every optional ACP feature or migrating to another protocol major.
