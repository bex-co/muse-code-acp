## Objective

Turn the existing SDK spike into an explicit compatibility contract so later work depends on verified public APIs and an honest advertised ACP surface.

## Context

- package.json currently pins @muse-code/sdk 0.1.1 and @agentclientprotocol/sdk 1.3.0; README records a local Muse 1.1.1 smoke, not a proven universal minimum.
- The SDK's public MuseClient/Session layer provides turn routing, approvals, and gap fill. Inventory user-input, session-history, config, and cancel verbs from shipped declarations before relying on them.

## Steps

1. Inventory current behavior and map each planned ACP operation to a public SDK API, a typed MSP command, or a named compatibility fallback.
2. Verify and pin the minimum supported host/SDK combination using the serve help surface and initialize capability/schema evidence; handle fingerprint differences according to the documented compatibility policy.
3. Add executable startup checks for missing serve support, disabled SDK support, and unsupported required capabilities; document which failure requires upgrading the host.
4. Create docs/sdk-migration.md with the compatibility/support matrix, test owners, and remaining CLI helpers; upgrade the ACP SDK only if a planned standard feature requires a published compatible version.

## Acceptance criteria

- [ ] Supported startup and unsupported/disabled-host cases have deterministic tests and actionable errors before model submission.
- [ ] Exact package pins, verified host requirements, and the public API or fallback for every planned behavior are documented.
- [ ] No undeclared MSP methods, private SDK imports, invented capability fields, or unsupported protocol versions are introduced.

## Out of scope

- Default-backend changes, broad dependency upgrades, and replacing ancillary CLI helpers merely to eliminate every subprocess.
