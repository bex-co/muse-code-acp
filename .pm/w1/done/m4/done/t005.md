## Objective

Stop silently dropping editor-supplied resource links so the SDK execution path satisfies ACP's baseline prompt-content contract.

## Context

- src/acp-agent.ts promptToText currently collects text blocks only; SDK turn/start receives a single flattened text input.
- The reference attachment test in CodexAcpClient.test.ts covers mixed content. Use Muse's declared input types, with a documented lossless text representation if a direct resource-link type is absent.

## Steps

1. Introduce a shared prompt-content conversion boundary that preserves ordered text, resource URI/name/description, Unicode, and link-only prompts.
2. Map supported content into public SDK input types and the legacy exec representation without reading arbitrary resource URIs as a side effect of conversion.
3. Give unsupported optional content an explicit capability-aware result instead of silently discarding it.
4. Assert exact semantic prompt content at the fake MSP/exec boundary and through the spawned ACP harness.

## Acceptance criteria

- [ ] Text-only, link-only, mixed text/link, file URI, and Unicode cases reach Muse with their content and order preserved.
- [ ] Valid resource-only prompts are accepted; empty or malformed input fails without starting a turn.
- [ ] Optional images/audio/embedded content are neither advertised nor silently accepted unless implemented and tested.
- [ ] Common baseline prompt contracts pass for sdk and exec.

## Out of scope

- Fetching arbitrary URLs, adding image/audio support, and implementing editor filesystem delegation.
