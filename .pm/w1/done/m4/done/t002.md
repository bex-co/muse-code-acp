## Objective

Exercise the same byte transport and executable that editors use, making serialization and process-lifecycle regressions visible in normal tests.

## Context

- src/tests/helpers.ts currently drives the real ACP SDK connection without a transport; src/tests/smoke.test.ts checks package identity only.
- The reference's typed-session-failure-wire fixture and e2e/spawned-agent-fixture show NDJSON connections and restartable processes; reuse the pattern with Muse-specific fixtures.

## Steps

1. Add a harness that launches the built entrypoint, configures a fake MSP executable, and connects an ACP client over stdin/stdout.
2. Record both ACP and fake-MSP messages, support client request responders, and allow explicit event barriers, delayed acknowledgements, fragmented frames, and process restart.
3. Isolate workspace/settings/data directories and guarantee teardown on success or assertion failure.
4. Add a representative initialize/new/prompt/response smoke; wire the test command to build the entrypoint first.

## Acceptance criteria

- [ ] The test spawns dist/index.js and uses actual NDJSON serialization in both directions.
- [ ] One test verifies fragmented/coalesced traffic, matching request IDs, no responses to notifications, and diagnostics on stderr rather than stdout.
- [ ] Harness cleanup leaves no owned process or temporary overlay behind; timeouts provide useful transcripts without credentials.
- [ ] The harness works without Muse credentials, a real provider, or the .tmp checkout.

## Out of scope

- Graphical editor automation, rebuilding ACP transport internals, and copying Codex-specific extension schemas.
