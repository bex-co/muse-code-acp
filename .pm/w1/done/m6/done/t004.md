## Objective

Keep login, logout, auth failures, and skill commands usable after SDK default cutover, with truthful client capability negotiation.

## Context

- src/auth.ts uses existing Muse CLI auth helpers and META_API_KEY; src/skills.ts provides slash commands.
- m4 establishes terminal-auth capability filtering; reference initialize/auth tests and command tests supply capability-on/off and failure patterns.

## Steps

1. Exercise absent credentials, configured dummy credentials, typed mid-turn auth failure, logout, and reauthentication on the SDK path.
2. Keep terminal login available only to compatible clients and retain the documented --cli login helper where the SDK has no equivalent.
3. Verify logout invalidates applicable stored authentication without falsely claiming to remove an externally supplied environment key.
4. Test advertised skill commands reaching SDK prompt input, failed command discovery, and suppression of stale discovery updates after session disposal.

## Acceptance criteria

- [ ] Auth failures arrive over ACP as auth-required errors, and a successful configured reauthentication allows a later prompt.
- [ ] Login methods respect peer capabilities; logout behavior for stored credentials versus META_API_KEY matches documentation and tests.
- [ ] Every advertised command is invocable on the SDK backend with correct prompt content.
- [ ] Auth/command failure and late discovery events neither leak secrets nor corrupt another session.

## Out of scope

- New browser/OAuth UX, removing supported CLI login solely for architectural purity, and exposing credentials in test transcripts.
