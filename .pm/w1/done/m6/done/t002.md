## Objective

Prove loaded ACP history is complete, ordered, and consistent with the resumed conversation rather than a partial snapshot that happens to render.

## Context

- Reference thread-history.test.ts checks every page, replay boundaries, repeated cursors, and later-page failures.
- Current exportToUpdates and list/load tests can provide legacy fixtures; SDK view/history fixtures must use the public schema and the selected history path.

## Steps

1. Add multi-page/multi-turn fixtures with user messages, agent messages, tool calls/results, Unicode content, and completion-only tool items.
2. Anchor replay at the load/resume boundary when paging is available so live appended turns are not replayed twice.
3. Test empty pages, corrupt/missing history, repeated or cycling cursors, later-page failure, and stale load completion after session teardown/reopen.
4. Ensure all replay updates precede the successful load response and later live updates retain consistent identities; apply equivalent all-or-error assertions to the export fallback.

## Acceptance criteria

- [ ] Every expected history item appears once in chronological order with stable tool/result relationships.
- [ ] History appended during paging is handled at the documented replay boundary without lost or duplicated live updates.
- [ ] Broken pagination/export rejects the load instead of returning success with an incomplete transcript, and failed state cannot leak into a later load.
- [ ] The same visible legacy fixture history survives load before and after selecting the SDK backend.

## Out of scope

- Whole-store rewrites, inventing unsupported history APIs, and accepting incomplete replay as a successful load.
