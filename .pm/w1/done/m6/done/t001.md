## Objective

Connect ACP session operations to supported SDK session state while keeping existing Muse conversations usable and avoiding partially loaded adapter sessions.

## Context

- Session list/load currently reads the Muse store and exports history through CLI helpers; loadSession publishes local state before export succeeds.
- The SDK exposes typed start/resume/opening results, with additional operations determined by the verified support matrix. Existing CLI session IDs may be UUIDv4 rather than UUIDv7.

## Steps

1. Use public SDK/typed MSP operations for supported session creation, resume, and metadata; preserve the established store/export fallback only where required for legacy complete history.
2. Validate identity, workspace, active-turn ownership, and durable profile before publishing a loaded adapter session.
3. Make failed load/resume clean up acquired state and subscriptions; do not replace corrupt/busy/missing history with a fresh session except for the explicit new-session path.
4. Preserve list filtering, titles, timestamps, pagination, and legacy ID acceptance, and document any retained fallback boundary.

## Acceptance criteria

- [ ] New SDK sessions use valid SDK-generated identity; existing UUIDv4 sessions resume without rewriting their IDs or logs.
- [ ] Wrong-workspace, busy, corrupt, and failed-export/resume cases leave no half-loaded session usable for prompting.
- [ ] List/load exposes complete metadata and correct workspace boundaries, with tests for missing/corrupt entries and pagination.
- [ ] Every retained CLI/store helper has a named compatibility reason; normal prompt execution uses only the SDK backend.

## Out of scope

- Session deletion/forking, mutating legacy logs, and implementing private session-store migrations.
