## Objective

Preserve client-supplied MCP tools and their per-session configuration through the SDK migration without changing users' persistent settings.

## Context

- src/mcp-overlay.ts merges ACP stdio MCP servers into a private per-turn settings overlay; existing SDK tests cover a basic readOnly/overlay path.
- Reference mcp-config-merge.test.ts and load-session.test.ts cover configuration conflicts and requested-server startup failures. Preserve this project's documented merge policy rather than copying Codex's.

## Steps

1. Test user/client MCP configuration conflicts, arguments/environment, same-name servers in independent sessions, and replacement/removal on load.
2. Verify serve receives the intended overlay for the entire turn, including pending approvals/input, and never mutates the user's settings.
3. Exercise server startup failure, cancellation, host crash, and client disconnect; require overlay cleanup after every terminal path.
4. Keep HTTP/SSE/other transports unadvertised until actually implemented; test the existing explicit handling for unsupported server types and document it.

## Acceptance criteria

- [ ] The intended per-session stdio MCP configuration reaches Muse and conflicts follow the documented precedence.
- [ ] MCP configuration never bleeds between sessions or resurrects a server omitted by the newly loading client.
- [ ] Persistent settings remain unchanged and temporary overlays exist only for their required lifetime, including error and cancellation cases.
- [ ] Startup failures and unsupported transports have deterministic, documented client-visible handling.

## Out of scope

- Adding remote MCP transports, client filesystem/terminal proxying, and changing user-global settings.
