## Objective

Demonstrate that a real ACP process can restart and continue the same Muse conversation, closing the gap left by in-process tests and the reference's skipped persistence case.

## Context

- src/tests/muse-sdk-live.test.ts uses a real Muse host but recreates in-process ACP clients; m4 adds the spawned entrypoint harness.
- Use the existing loopback provider and isolated settings/data directories. The provider can inspect conversation payloads deterministically without paid model calls.

## Steps

1. Run initialize/new/two prompts through the built ACP binary and assert streamed output and actual provider context.
2. Terminate and restart the ACP process with the same isolated data directory, list/load the session, verify history/configuration, then continue the conversation.
3. Cancel a running turn and verify a later prompt succeeds; include the real approval cases from m5 and readOnly effects from the configuration task.
4. Create one legacy CLI UUIDv4 session in the same test environment and continue it through the SDK-backed ACP process without rewriting its stored history.

## Acceptance criteria

- [ ] The adapter process itself is restarted, not only the Muse host or an in-process class instance.
- [ ] The provider receives prior conversation context after restart and the ACP client observes complete history before the new response.
- [ ] SDK UUIDv7 and legacy UUIDv4 sessions both continue successfully with their original IDs.
- [ ] Cancel/continue and mode/approval effects pass using a real local host and no external provider traffic.
- [ ] A missing required real-host prerequisite fails explicitly when this integration suite is selected.

## Out of scope

- Graphical editor automation, nondeterministic model-memory assertions, and marking a skipped restart case as covered.
