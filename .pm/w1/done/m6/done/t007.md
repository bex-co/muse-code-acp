## Objective

Make migration confidence reproducible from a clean checkout and prevent missing Muse installations from silently turning critical integration coverage green.

## Context

- Current CI builds and runs npm run test:run; local real-Muse tests automatically skip when prerequisites are absent.
- The ignored .tmp/codex-acp checkout must not be required. Real-provider integration remains separately opt-in because local loopback tests can cover the critical behavior deterministically.

## Steps

1. Define clear scripts/profiles for deterministic unit/wire tests, real-Muse loopback integration, and optional external-provider acceptance.
2. Add a required CI integration job that provisions the verified compatible Muse binary on a supported platform and fails if required tests cannot run.
3. Build before spawned-entrypoint tests, isolate environment/filesystem state, and capture redacted ACP/MSP transcripts on failure without blanket retries.
4. Add a local tarball installation smoke that initializes and runs a fixture-backed prompt from outside the repository using the packed entrypoint and dependencies.

## Acceptance criteria

- [ ] A clean checkout runs deterministic contract tests without Muse credentials or a local reference checkout.
- [ ] The required real-host job installs the documented binary version and executes approval and ACP-process restart cases; missing prerequisites or zero selected tests fail the job.
- [ ] Optional external-provider results are separate from required local integration evidence.
- [ ] A locally packed install works over stdio outside the repository and contains the runtime SDK dependency and expected executable.
- [ ] Required checks preserve failure signals rather than using retry-to-green or broad test skips.

## Out of scope

- Public npm publishing, expanding to unclaimed platforms, and making paid live-provider access a default PR requirement.
