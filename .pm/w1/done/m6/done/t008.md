## Objective

Complete the migration for normal users after the critical test gates pass, with an explicit and reviewable legacy compatibility path.

## Context

- MUSE_CODE_ACP_BACKEND currently defaults to exec and sdk is opt-in; README still presents Muse >=0.2.1 as the general minimum.
- m4-m6 establish which behavior is shared and which capabilities differ. Default/readOnly are sufficient for the minimal SDK cutover; unsupported dangerous modes remain legacy-only.

## Steps

1. Select SDK when no backend override is set, preserve explicit exec selection, and reject unknown backend selectors with an actionable error.
2. Update tests that intentionally cover echo/legacy behavior to choose exec explicitly; run common ACP contracts under both backend selections and the default.
3. Update README, environment settings, minimum host requirements, capability matrix, mode descriptions, and migration/rollback documentation to match tested behavior.
4. Remove superseded spike-only paths and stale comments only where public SDK behavior has replaced them; retain documented ancillary CLI helpers and avoid automatic backend fallback.

## Acceptance criteria

- [ ] An installed adapter with no backend variable completes the required ACP flow through the SDK; the wire transcript contains no exec turn execution.
- [ ] Explicit exec selection still passes the documented legacy contracts; invalid selectors and incompatible SDK hosts fail clearly.
- [ ] SDK failure never triggers a second possibly side-effecting turn through the legacy backend.
- [ ] Documentation matches actual advertised capabilities, verified host requirements, retained helpers, mode differences, and the explicit rollback command.
- [ ] All required wire and real-host tests pass against the changed default before the closing tasks mark the milestone complete.

## Out of scope
