## Objective

Pin `@muse-code/sdk` 1.4.14 and make Muse 1.4.14-R7309.1 a verified, CI-tested host.

## Context

- 1.4.14 schema diff from 1.4.13, all additive:
  - Approvals: `reviewerReason` on approval requests.
  - Tool calls: `held` / `heldFor` on `toolCall` items.
  - Replay: item kind `earlierHistory`.
  - Messages and turns: `wakeSourceDescriptions` on `agentMessage`; `requestDenied` on live `turn/completed`.
  - Session reads: `driveHolder`, `resumedByClient`, `spawnedBy`, `itemCount` and `logBytes`; `worktree` on child reads.
  - Requests: `modelId` on `session/resume`; `previousSessionId` and `spawnedBy` on `session/start`; `maxBytes` on `view/page`.
- `WORKFLOW_CANCEL_HOSTS` (`src/muse-sdk-host.ts`) gates workflow cancel per verified host. 1.4.14 passed `async-tasks-live` 4/4 locally once added (2026-10-28).
- Linux binary: `x86_linux` SHA-256 `0809aac7cb58d18f5022b6d05e02aa1974683c0ec430e5f04d25b60ed17de2da` (from the 1.4.14-R7309.1 manifest).

## Steps

1. Bump the exact pin in `package.json`/lockfile and `SDK_PACKAGE`; add 1.4.14 to `VERIFIED_MUSE_HOSTS` and `WORKFLOW_CANCEL_HOSTS`.
2. Move the CI newest-host leg (`.github/workflows/ci.yml`) to 1.4.14-R7309.1 with the SHA above.
3. Classify each schema addition in `src/muse-view-events.ts` (or the event translator): adopted (t002, t004) or ignored with a reason. Candidates to record as not adopted: `held`/`heldFor`, `requestDenied`, `driveHolder`, `modelId` on resume.
4. Run the loopback suite on 1.4.14 with `MUSE_CODE_ACP_REQUIRE_HOST_FEATURES=all`, plus the 1.1.1 baseline.
