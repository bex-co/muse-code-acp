## Objective

Each fixed upstream issue is handled by host version. On affected hosts the user gets an actionable message; on 1.4.14+ the workaround stays harmless, and a regression shows up as a new QA finding instead of a "known" one.

## Context

- #120 (Linux fork on 1.4.12/1.4.13): the adapter forwards Muse's "file birth time is unavailable".
- #112 (1.4.11–1.4.13): after resuming a compacted session with MCP servers, turns fail with "MCP startup audit failed; MCP is disabled for this runtime". Not worked around.
- #121 (1.4.12/1.4.13): the resume reports a phantom `activeTurnId`. `src/muse-sdk-host.ts` already ignores it unless `pendingRequests` exist, so keep that for older hosts.
- `/qa-find-bugs` `analyze.mjs` `KNOWN` tags these regardless of host version.

## Steps

1. On the SDK backend, when a fork fails with the birth-time error, or a turn fails with the MCP startup audit error, append "fixed in Muse 1.4.14; update Muse" to the reported message. Match on Muse's error text only, never guess.
2. Keep the #121 admission behavior and document it as needed for 1.4.12/1.4.13 only.
3. Make `analyze.mjs` and the QA scenarios tag #112/#120/#121 as known only on affected host versions. On ≥1.4.14, a phantom-active-turn log line or an MCP audit failure is a new finding.

## Files

- `src/session-lifecycle.ts`, `src/sdk-prompt-turn.ts` (or the failure reporter), `.agents/skills/qa-find-bugs/scripts/analyze.mjs`, `.agents/skills/qa-find-bugs/scenarios.md`, matching unit tests

## Acceptance criteria

- [x] Unit tests: the fork birth-time and MCP-audit failures carry the upgrade hint; other errors are unchanged.
- [x] `analyze.mjs` run against a 1.4.14 QA dir whose stderr contains the phantom log reports it as a new finding.

## Out of scope

- Retrying or re-routing failed operations on older hosts.

## Evidence

- `src/upstream-fixes.ts` matches only Muse's own error text. The fork failure (`src/session-fork.ts`) and turn failures (`src/turn-failure.ts`) append "Muse 1.4.14 fixes …; update Muse" for "file birth time is unavailable" (#120) and "MCP startup audit failed" (#112). Unit tests: `session-fork-host.test.ts` (birth time vs. an unrelated internal error) and `turn-failure.test.ts` (MCP audit vs. an unrelated failure).
- #121: admission behavior kept for 1.4.12/1.4.13; the comment in `src/muse-sdk-host.ts` notes the 1.4.14 fix.
- `analyze.mjs`: `KNOWN` entries carry affected `hosts`, and the host version comes from `results.json`. There is a new stderr check for "resumed session reports active turn". Synthetic QA dirs: on 1.4.14 both the #112 finding and the phantom are reported as NEW; on 1.4.13 they are tagged #112/#121. `scenarios.md` updated.
