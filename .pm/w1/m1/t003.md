## Objective

Stand up the ACP server: ndjson-over-stdio transport, the `AcpClient`/`ClientConnection` choke point, `initialize` with honest (minimal) capabilities, and `session/new` that mints a session UUID bound to a cwd.

## Context

- Pattern source: `claude-agent-acp/src/acp-agent.ts:8471-8519` (`runAcp`) and `:1277-1345` (`AcpClient` interface + `ClientConnection`). Reuse the structure, not the file.
- Capabilities for m1: `promptCapabilities: {}` (text only), no `loadSession`, no auth methods yet, `agentInfo` from package.json. Grow per milestone — never advertise what isn't implemented.
- `session/new`: generate UUID (becomes `--session-id` later), store `{cwd}` in an in-memory session map. Muse creates its on-disk log lazily on first exec.

## Steps

1. `acp-agent.ts`: `MuseAcpAgent` class + `runAcp()` registering `initialize`, `session/new`, `session/prompt` (stub), `session/cancel` (stub) via `@agentclientprotocol/sdk`.
2. Define `AcpClient` interface + `ClientConnection` wrapper (sessionUpdate, requestPermission, readTextFile, writeTextFile — even if unused yet, keep the seam).
3. Session registry: map ACP sessionId → `{cwd, child?, museSessionId}`.
4. Harness test: connect a fake ACP client over paired streams, assert `initialize` response shape and `session/new` returns a fresh id per call.
