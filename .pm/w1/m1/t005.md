## Objective

Connect the two halves: `session/prompt` spawns the runner for the session, translates `run.output.delta` → `agent_message_chunk` notifications, resolves on `run.terminal.*`, and `session/cancel` SIGINTs the child.

## Context

- One child per turn; the session map holds the live child so cancel can find it. Reject concurrent prompts on one session (ACP allows queuing later; keep m1 strict).
- Stop-reason mapping: `run.terminal.completed` → `end_turn`; exit 130/143 or cancel → `cancelled`; exit 1 with `run.terminal.failed` → error result; exit 2 → internal error.
- `turn.input.user` echoes the prompt back — suppress (don't re-emit the user's own text).

## Steps

1. Implement `prompt()` on `MuseAcpAgent`: guard → spawn via runner → for-await events → `ClientConnection.sessionUpdate` → return stop reason from outcome.
2. Implement `cancel()`: look up child, SIGINT, await `done`, ensure prompt resolves `cancelled` exactly once.
3. End-to-end test: fake ACP client sends prompt against echo provider (with `--echo-delay-ms` for the cancel case), asserts chunk stream, stop reasons, and single-resolution invariants.

## Files

- `muse-code-acp/src/acp-agent.ts` (prompt/cancel), `src/translate.ts` (delta → chunk)
- `muse-code-acp/src/tests/prompt.test.ts`

## Acceptance criteria

- [ ] Echo turn: prompt "hello" yields ≥1 `agent_message_chunk` containing `echo: hello` then `end_turn`
- [ ] Cancel mid-turn resolves `cancelled`, child is reaped (no zombie), and a follow-up prompt on the same session works
- [ ] Concurrent prompt on a busy session is rejected with a clear ACP error

## Out of scope

- Tool-call events, diffs, permission modes, `--session-id` continuity semantics beyond passing the flag (m2)
