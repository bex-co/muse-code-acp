## Objective

Implement ACP `session/list`: enumerate this workspace's past Muse sessions with ids, timestamps, and a usable title, and advertise the `list` session capability.

## Context

- Store layout: `~/.local/share/muse/sessions/YYYY/MM/DD/` containing per-session logs (`session.jsonl`). Exact per-session directory/file naming needs empirical verification (create two sessions, inspect).
- Workspace filtering: sessions record their workspace; only list sessions matching the ACP session cwd (same behavior the `muse resume` picker has). Determine where workspace is recorded (log header vs path) during implementation.
- Title source: first user prompt (from `turn.input.user` in the log head) truncated; muse has no AI-title facility to reuse.
- Read-only: never mutate the store. `session/delete` is deliberately not implemented (muse documents no delete; don't invent one).

## Steps

1. Probe the store layout with two throwaway echo sessions (temp data dir); document it in a comment.
2. Implement the store reader: scan date dirs, parse minimal log head (session id, workspace, first prompt, timestamp) without loading full logs.
3. Wire `session/list` + capability flag; sort newest-first; cap and paginate per ACP norms.
4. Tests against a fabricated temp store.

## Files

- `muse-code-acp/src/session-store.ts`, `src/acp-agent.ts`
- `muse-code-acp/src/tests/session-store.test.ts`

## Acceptance criteria

- [ ] List returns only current-workspace sessions, newest first, with non-empty titles
- [ ] A corrupt/truncated log file is skipped with a logged warning, never a crash
- [ ] Large store (hundreds of sessions) lists without reading full logs (only heads)

## Out of scope

- History replay (t002); deleting sessions (not supported by muse)
