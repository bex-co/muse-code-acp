## Objective

Implement ACP `session/load`: given a listed session id, replay its transcript (user/agent messages, tool calls with results) as ACP updates, then allow the conversation to continue with a normal `session/prompt`.

## Context

- Transcript source: `muse export --session <id> --out <tmpfile>` — self-contained JSON (`export_schema_version: 1`) with timestamps, messages, tool calls/results, approvals, fork/subagent lineage. Prefer export over raw log parsing (stable, documented schema). Use `--redacted` never — it strips auth headers but we're local; plain export, delete the tmpfile after.
- Reuse m2's translator: export records → the same ACP update emission path as live events (this is why m3 depends on m2).
- Continuation: after replay, the session map binds the ACP session to the existing muse session id; next prompt is `muse exec --session-id <id>`.
- Reference: `claude-agent-acp` `replaySessionHistory` (`acp-agent.ts:5057`) for pacing/ordering conventions.

## Steps

1. Export runner: spawn `muse export`, parse the JSON document, map export records → translator inputs; document the record kinds encountered.
2. Implement `loadSession`: replay updates in order, advertise `loadSession` capability.
3. Integration test (echo provider, temp store): create a 2-turn session, load it fresh, assert replayed updates match the live ones, then continue with a third prompt.

- [ ] Replayed history for a tool-using session includes tool_call updates with results, in original order
- [ ] Prompting after load continues the same muse session (verified via session log sequence continuity)
- [ ] Encrypted-reasoning blobs in exports are skipped silently (no thought chunks fabricated)
