## Objective

Give editor users a working auth story: advertise ACP auth methods for browser login (via the `--cli` passthrough exec-ing `muse login`) and API key (`META_API_KEY` / stored key), detect the authenticated state, and implement `logout`.

## Context

- Muse auth surface (verified): `muse login` (browser OAuth), `muse logout`, `muse auth set --api-key-stdin`, env `META_API_KEY`; precedence env > stored key > browser session; state in `~/.config/muse/auth.json`.
- Pattern: `claude-agent-acp` advertises auth methods whose `args` re-invoke the adapter binary with `--cli auth login …` (`acp-agent.ts:1505-1544`); mirror with `--cli login`.
- Detection: presence of `META_API_KEY` or a non-empty `auth.json` → authenticated; on m2's auth-classified turn failure, return the ACP auth-required error so clients show the login flow.
- `logout`: exec `muse logout`; note it cannot unset the user's exported env var — say so in the result.

## Steps

1. Auth-state probe (env + auth.json presence; no secret parsing).
2. Advertise auth methods in `initialize`; implement `authenticate`/`logout` handlers.
3. Wire m2's auth-failure classification → ACP auth-required error.
4. Tests with temp HOME: unauthenticated flow, env-key flow, logout messaging.

## Acceptance criteria

- [ ] Unauthenticated + no env key → initialize advertises both auth methods; auth-required error carries actionable text
- [ ] `--cli login` execs the real `muse login` with inherited stdio
- [ ] No secret material is ever read into adapter memory or logs (auth.json checked for existence/size only)
