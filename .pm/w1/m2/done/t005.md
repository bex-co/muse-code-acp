## Objective

Let clients pick the model and reasoning effort per session via ACP config options, defaulting from the user's Muse settings.

## Context

- Known models: `muse-spark-1.2`, `muse-spark-1.2-contributor`; effort levels `none|minimal|low|medium|high|xhigh|ultra` (default high). Flags: `--model`, `--reasoning-effort` at spawn time.
- Defaults source: `~/.config/muse/settings.json` (`schema_version: 1`, keys `provider`, `model`, `reasoning_effort`) — read-only; never write this file.
- Pattern: claude-agent-acp's `EffortLevel` config option (`session/set_config_option`, config ids in `src/session-config-ids.ts`).
- No dynamic model-list API exists — ship a static list with the settings-file value injected if unknown, and make the list easy to extend.

## Steps

1. Settings reader with graceful absence/malformed handling (missing file → hardcoded defaults).
2. Config-option registry: `model` (select), `reasoningEffort` (select); wire `session/set_config_option`; apply at next spawn.
3. Tests: default resolution order (explicit option > settings.json > built-in), argv assembly, malformed settings.

## Files

- `muse-code-acp/src/muse-settings.ts`, `src/config-options.ts`
- `muse-code-acp/src/tests/config-options.test.ts`

## Acceptance criteria

- [ ] Fresh session reflects settings.json model/effort; overrides apply on next spawn's argv
- [ ] Malformed or absent settings.json never crashes the adapter (logged warning only)
- [ ] Config options advertised in the session/new response match what set_config_option accepts

## Out of scope

- Provider switching (`--provider`, `--base-url`) — inbox-note material if requested
