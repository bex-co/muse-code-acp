## Objective

Translate Muse tool activity into ACP tool-call updates: `task.lifecycle.side_effect_intent` (`operation: "tool:*"`) opens a pending `tool_call`; `task.lifecycle.output` streams progress; `tool.result` (keyed by `call_id`, with `correlation_facts.tool_name`/`outcome`) completes it.

## Context

- Verified shapes (muse 0.2.1, real provider): `side_effect_intent` carries `operation: "tool:bash"`, `idempotency_key: "tool:call_…"`, `policy_decision: "allow:policy"`; `tool.result` carries `call_id`, `text` (JSON blob for bash: command, exit_code, output, truncated), `correlation_facts: {tool_name, outcome}`.
- The `call_id` inside `idempotency_key` links intent → result; maintain a per-turn map.
- Tool-kind mapping: `bash` → execute; edit/write tools → edit; read tools → read; unknown → other. Enumerate actual muse tool names from a recorded real-provider fixture during implementation.
- Surface `policy_decision` as tool-call metadata so clients can show why something ran (this is the honest substitute for interactive permission UI — see DO_NOT_DO).
- Suppress internal noise: `model.*.response` tasks, observer/reminder tasks (`reminder.agent.plugin:*`), `task.stream.linked`.

## Steps

1. Record one real-provider fixture (shell command + file read) into `src/tests/fixtures/real-*.jsonl`; scrub tokens.
2. Extend `translate.ts`: intent → `tool_call` (pending, kind, title from command/description), output → `tool_call_update` (in_progress, content), `tool.result` → `tool_call_update` (completed/failed by `outcome`).
3. Parse the bash result JSON blob into structured content (command, exit code, output) with graceful fallback to raw text.
4. Fixture-driven tests for the full sequence and for orphan results (result with no seen intent).
