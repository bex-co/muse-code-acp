## Objective

When Muse edits or writes a file, surface the change as ACP diff content on the tool_call update so editors render a proper diff view.

## Context

- Open question from research: the exact result shape of Muse's edit/write tools is unverified — capture it from a real-provider fixture first (a turn that edits an existing file and creates a new one).
- Muse applies edits itself inside its sandbox; the adapter reports after the fact (codex-acp model). If the result payload lacks old/new content, fall back to reading the file post-result and diffing against a pre-intent snapshot — but prefer payload data.
- Reference for the ACP diff shape: `claude-agent-acp/src/tools.ts` `toolUpdateFromDiffToolResponse` (`tools.ts:1298`).

## Steps

1. Record the edit/write fixture; document the tool names and result schema in a comment block.
2. Implement diff extraction → ACP `content: [{type: "diff", …}]` on the completing update; plain-content fallback when reconstruction is impossible.
3. Tests from fixtures: modify, create, and a failed edit.

## Files

- `muse-code-acp/src/tool-calls.ts`
- `muse-code-acp/src/tests/tool-calls.test.ts`, fixtures

## Acceptance criteria

- [ ] Edit turn fixture yields a tool_call update containing a diff with correct path, old and new text
- [ ] New-file creation renders as a diff from empty
- [ ] When diff data is unavailable the update still completes with textual content (never throws)

## Out of scope

- Proxying edits through ACP `fs/write_text_file` (impossible — muse writes directly; documented degradation)
