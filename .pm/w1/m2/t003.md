## Objective

Make failures honest: map Muse's failure signals (`run.terminal.failed`, `task.lifecycle.failed` on the main task, nonzero exits, `--max-model-steps` exhaustion) to ACP error surfaces and correct stop reasons instead of a silent `end_turn`.

## Context

- Research caveat: "exit codes describe run completion, not code correctness" — exit 0 with the agent reporting failing tests is still `end_turn`; only run/turn-level failures are errors.
- Known taxonomy: exit 1 = failed or cancelled (disambiguate via terminal event vs signal), 2 = usage error (adapter bug — surface loudly), 130/143 = signals. Auth failures and model-stream retry exhaustion appear as `task.lifecycle.status` phases + `failed` reasons (e.g. "invalid run configuration…" observed on the echo provider).
- Reference: claude-agent-acp's session-failure extension pattern (`src/session-failure-extension.ts`) — a trimmed version can carry structured failure info to capable clients.

## Steps

1. Build the outcome resolver: (exit code, last terminal event, cancel flag) → stop reason or ACP error with message.
2. Emit a final `agent_message_chunk`/error containing the failure reason when a run fails mid-turn.
3. Classify auth/quota failures distinctly (feeds m3's auth UX).
4. Tests per taxonomy row, using doctored fixtures + killed echo children.

## Acceptance criteria

- [ ] Every (exit code × terminal event presence) combination has a deterministic, tested mapping
- [ ] A `--max-model-steps`-exhausted run surfaces as `max_turn_requests`-style stop, not `end_turn`
- [ ] Usage errors (exit 2) produce an internal-error report that names the spawned argv

## Out of scope
