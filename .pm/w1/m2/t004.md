## Objective

Expose ACP session modes that map honestly onto Muse's headless safety levers: a default mode (muse policy + LLM judge decide; adapter reports decisions) and a bypass mode (`--disable-approval`, sandbox kept on; `--yolo` only as an explicit third mode).

## Context

- Hard constraint (verified): muse 0.2.1 headless has no interactive approval channel — `exec` rejects `--approval-mode`; approvals resolve internally (`policy_decision: "allow:policy"`). Per DO_NOT_DO, never fake a `session/request_permission` gate.
- Mode table: `default` → no safety flags (on-request + judge + sandbox); `bypassApprovals` → `--disable-approval`; `yolo` → `--yolo` (approval + sandbox off, workspace trusted) — gated behind an env opt-in and never default; consider `readOnly` → `--disable-write --disable-shell` as a cheap fourth mode.
- Mode is applied at spawn time — `session/set_mode` takes effect on the next prompt; document this latency in the mode description strings.
- Reference pattern: `claude-agent-acp/src/session-mode.ts` (mode manager), `permissions/modes.ts` (root guard — keep an equivalent: no bypass/yolo as root).

## Steps

1. Define the mode registry with names, descriptions (stating "applies from next prompt"), and flag sets.
2. Implement `session/set_mode` + advertise modes in `session/new` response; persist per session.
3. Root/uid-0 guard refusing bypass modes.
4. Tests: flag assembly per mode, set_mode round-trip, root guard.
