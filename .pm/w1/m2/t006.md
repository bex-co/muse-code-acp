## Objective

Verify and harden multi-turn behavior: consecutive prompts on one ACP session reuse the same Muse `--session-id` and genuinely share conversation state, including after a mid-turn cancel.

## Context

- Muse's intent-before-effect journal with idempotency keys makes kill-and-resume safe by design (research: killed migration resumed with zero duplicate side effects) — the adapter should lean on this, not reinvent it.
- Session logs live under `~/.local/share/muse/sessions/YYYY/MM/DD/`; tests must not pollute the real store — point `XDG_DATA_HOME`/`HOME` at a temp dir in integration tests (verify which env var muse honors).
- `--allow-workspace-switch` exists for cwd mismatch on resume; decide policy (probably: pass it never; error clearly instead).

## Steps

1. Integration test (echo provider, session log enabled, temp data dir): two prompts, assert both runs land in one session log with increasing sequence numbers.
2. Cancel turn 1 mid-run, send turn 2, assert clean continuation (no error, no duplicate events).
3. Workspace-mismatch test: same session id from a different cwd → assert the adapter's chosen behavior (clear error).
