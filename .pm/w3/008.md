# 008 — Surface Muse reviewer decisions and decide on reviewer control

Why: From Muse 1.4.6, `muse serve` runs the automated approval reviewer, so SDK-backend tool calls it approves run without any ACP permission prompt, and the client cannot tell why.

Evidence (w3/m7, 2026-10-12, Muse 1.4.6-R6000.1): with the loopback reviewer approving, the SDK approval live tests received no `session/request_permission` and the "deny" marker was written; with the reviewer escalating, approvals reach the client as before. The protocol already carries `judgeEscalated` on approval requests and `resolvedBy: "llmJudge"` on `approval/resolved` (since SDK 1.4.4). Serve has no reviewer flag, but accepts `-c KEY=VALUE` settings and the binary knows an `approval_judge` setting.

Open decisions (user): (1) surface "approved by Muse's reviewer" on the tool card / a negotiated extension, and mark escalated requests as such; (2) whether to offer a reviewer on/off setting (default stays Muse's: on), verified to be a supported setting before exposing it. Respect DO_NOT_DO: no fabricated permissions; safety defaults unchanged.
