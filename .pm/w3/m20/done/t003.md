## Objective

`session/load` replays each prompt and reply as separate messages in clients that join adjacent chunks.

## Acceptance criteria

- [x] Replay chunks carry ACP `messageId` per prompt / committed reply.
- [x] Consecutive committed replies are separated by a blank line; a prompt with no recorded reply before the next prompt gets a short 'No reply was recorded' note.
- [x] Unit tests cover both cases.

## Evidence (2026-10-25)

`src/session-export.ts`: per-message ACP `messageId`, blank line between consecutive committed replies, "_No reply was recorded for this prompt._" for a prompt followed by another prompt or the end of history. Test: `session-history.test.ts` "keeps message boundaries clients would otherwise join"; existing replay tests unchanged.
