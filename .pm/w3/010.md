# 010 — Show native model retries as ACP notices

Why: Muse 1.4.8 now reports each provider retry before the turn ends, so clients could show "retrying, attempt N of M" instead of a silent wait, and ACP 1.8's stable `Notice` is the surface for it.

Estimate: a milestone (more than an hour). Source: w3/m17 t002/t003, 2026-10-15; meets the revisit trigger of [w1/006](../w1/006.md).

- Evidence: Muse 1.4.8-R6256.1, loopback provider answering 503: nine `turn/modelRetryScheduled` notifications (`attempt` 1→9, `nextAttempt`, `maxAttempts` 10, `retryDelayMs`, `errorKind: "server"`, `httpStatus: 503`), then `turn/completed` `terminal: "failed"`. The adapter classifies the event as ignored (`src/muse-view-events.ts`).
- Surface: `session/update` `notice` only for clients advertising `clientCapabilities.session.notices`; decide whether others get nothing or an agent message. Sibling `turn/retryScheduled` was never observed (w1/006 history).
- Needs a live test on 1.4.8+ gated through `hostSupports`, and the 1.1.1 baseline must stay quiet.
