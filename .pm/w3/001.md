# 001 — Exec backend offers `none`, which `muse exec` 1.4.x rejects for the meta provider

Why: An exec-backend user who picks `none` gets a failed turn instead of a usable effort choice.

Observed 2026-10-06 on Muse 1.4.2: `muse exec --reasoning-effort none` exits 2 with "--reasoning-effort none is not supported with --provider meta; choose minimal|low|medium|high|xhigh|max|ultra". The adapter's exec backend still offers `none` (`EFFORT_LEVELS` in `src/config-options.ts`); the SDK path maps `none` to `minimal` on 1.2.1+.

Acceptance: exec backend either omits `none` for the meta provider (feature-detected from `muse exec --help` / the error) or maps it truthfully; covered by a test.
