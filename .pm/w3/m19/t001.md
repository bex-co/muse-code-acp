## Objective

When the client negotiates them, the adapter emits the standard session state updates and error stop reasons that w3/m17/t003 classified as backed.

## Context

- Scope comes from the w3/m17/t003 classification; likely candidates are `StateUpdate` and `ErrorStopReason`.
- After w3/m18, emission belongs in the turn-runner and session-lifecycle modules.
- Failure data comes from `src/turn-failure.ts`; pending requests from the approval and user-input paths (`src/muse-permissions.ts`, `src/muse-user-input.ts`).

## Steps

1. Detect client negotiation at initialize, per the schema.
2. Emit state at defined transitions: turn start, pending approval or user input start and resolution, turn terminal, and idle after cancel.
3. Map turn failures to the standard error stop reason, preserving existing error data.
4. Leave the existing `muse/*` extensions unchanged as the fallback.

## Files

- src/acp-agent.ts and the modules extracted in w3/m18
- src/turn-failure.ts
- src/tests/

## Acceptance criteria

- [ ] Nothing is emitted unless negotiated (unit test).
- [ ] Each transition has a unit test, including steering, cancellation and background-task release, with no duplicate or out-of-order states.
- [ ] Failed turns carry the same failure data as before alongside the standard stop reason.

## Out of scope

- `CompactionUpdate` (w3/m9); types classified as unbacked or deferred.
