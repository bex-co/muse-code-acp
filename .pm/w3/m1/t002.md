## Objective

Never show the same model twice as `(meta)` and `(meta / tbh)`.

## Context

- Triage finding: when a turn runs before discovery completes, `src/acp-agent.ts` (around lines 1662/1670) pins `profileId: null`; `buildConfigOptions` then compares profiles strictly and injects the current selection as a separate entry. Sessions saved by earlier versions always stored `null` and hit the same path.

## Steps

1. When the current selection has no profile and exactly one catalog row matches its model and provider, adopt that row (in both `buildConfigOptions` and `resolvedModel`).
2. Do not pin `profileId: null` when discovery is unavailable; leave it undefined.
3. Keep an explicitly profiled selection that is absent from the catalog visible, as today.

- [ ] Tests cover: null-profile selection with one matching profiled row → single entry; ambiguous match (two profiles) → current selection kept distinct; restored legacy preference with `profileId: null` → single entry.

## Out of scope

- Changing how preferences are persisted on disk beyond the null/undefined distinction.
