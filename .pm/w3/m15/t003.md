## Objective

`npm run test:coverage` measures the deterministic suite and enforces non-regressing thresholds in CI.

## Context

- `package.json` `test:coverage` runs `vitest run --coverage`, but `@vitest/coverage-v8` is not installed, so the script fails immediately.
- `vitest.config.ts` configures the v8 provider without `include` or thresholds.
- `test:unit` excludes `src/tests/**/*-live.test.ts` and `src/tests/real-provider.integration.test.ts`; coverage must use the same exclusions.

## Steps

1. Add `@vitest/coverage-v8` pinned exactly to the installed Vitest version.
2. Make `test:coverage` use the `test:unit` exclusions.
3. Set `coverage.include` to `src/**/*.ts` and exclude `src/tests/**`.
4. Record baseline statement, branch, function and line percentages; set thresholds at the baseline rounded down to whole percents.
5. Run coverage in the CI build job, replacing the `test:unit` step if it is equivalent, so runtime does not double.
6. Make sure `coverage/` is ignored by git and Prettier and excluded from the package.
7. Add `npm run test:coverage` to the README testing command list.

## Files

- package.json, package-lock.json
- vitest.config.ts

## Acceptance criteria

- [ ] From a clean `npm ci`, `npm run test:coverage` succeeds and prints a summary.
- [ ] Baseline percentages are recorded in the milestone validation evidence.
- [ ] Dropping coverage below a threshold fails the command (shown with a temporary uncommitted change).
- [ ] The CI build job runs it, and `npm pack --dry-run` includes no coverage output.

## Out of scope

- Raising coverage targets; coverage for live suites.
