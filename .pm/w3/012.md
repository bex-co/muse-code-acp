# 012 — Make the loopback live suite reliable under local file parallelism

Why: `npm run test:muse-loopback` times out locally on macOS when the 21 files run in parallel, so a developer's local real-host check reports false failures; serial runs pass.

Estimate: 1h. Source: SDK 1.4.12 bump, 2026-10-23.

- Evidence (Apple Silicon, default vitest parallelism, otherwise quiet machine): Muse 1.4.8-R6256.1 → 8 of 68 fail; Muse 1.4.12-R6909.1 → 13 of 68 fail. Every failure is a test timeout or `expect.poll` timeout. The same suite with `--no-file-parallelism` passes 68/68 on 1.4.12.
- Likely factor: per-host startup. The w2/014 reproduction on 1.4.12 measured empty-store initialize at about 438 ms alone and about 2.1 s at 16 concurrent hosts (80 ms on 1.3.0).
- Options: cap `maxWorkers` for the loopback script, or scale the live timeouts. Keep CI's Linux job unchanged unless it also shows flakes on 1.4.12.
- Also seen in CI 2026-10-25 (run 40175456170, Muse 1.1.1-R2514.1 leg): `mcp-http-live` "preserves truthful diagnostics for ok endpoints" failed once with "session … is already in use", then passed on rerun. The code was unchanged.
