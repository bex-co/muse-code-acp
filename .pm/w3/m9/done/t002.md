## Objective

A `/compact` command compacts the session through public `session/compact` where the host completes it, and reports refusals truthfully.

## Context

- Muse 1.1.1/1.2.1 rejected compaction with -32030 `compaction_unavailable` (`docs/capability-audit.md`); unknown slash names, including `/compact`, are currently prompt text and must stay so on hosts that refuse.
- Advertise only what t001 verified; keep explicit unavailability elsewhere.
- ACP SDK 1.8.0 (w3/m17/t001) standardizes compaction reporting but not triggering. Clients advertise `clientCapabilities.session.compaction`; agents then send `CompactionUpdate` (`in_progress`/`completed`/`failed`/`cancelled`, optional summary and error) and `CompactionSummaryChunk`, and must not send them otherwise. Source: Muse `compaction` items (`outcome`, `reason`, `trigger`).

## Steps

1. Add `/compact` as the trigger over `session/compact`. Report the outcome as standard `CompactionUpdate`/`CompactionSummaryChunk` to clients that advertise `session.compaction`, and as the command's reply text otherwise. Do not add a custom compaction extension.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Files

- src/
- src/tests/

## Acceptance criteria

- [x] On hosts where compaction completes, `/compact` compacts without a model turn from the adapter and reports the outcome; on refusing hosts it is not advertised or fails with the host reason; history and continuation stay correct afterwards.
- [x] Clients advertising `session.compaction` receive the outcome as `CompactionUpdate` (plus `CompactionSummaryChunk` when Muse publishes a summary); other clients receive no compaction updates.

## Evidence (2026-10-25)

- Host acceptance first: real provider (`muse-spark-1.3`), Muse 1.4.12-R6909.1, throwaway workspace, user-approved. Raw SDK probe: `session/compact` → `accepted`; manual `compaction` item `inProgress` → `completed`, `outcome: compacted`, 30585 → 23051 tokens; next turn and a fresh-host resume both complete.
- Through the adapter (`/compact` over ACP, client advertising `session.compaction`): three turns, then `/compact` → `outcome: compacted` (30528 → 23084), item `trigger: manual`. The next turn recalled all three pre-compaction words ("apple, banana, cherry"). After an adapter restart, `session/resume` plus a new turn completed ("resumed"). Read back through public `session/resume` history; no model turn was run for `/compact`.
- Implementation: `MuseSdkHost.requestCompaction` (`src/muse-sdk-host.ts`) watches manual compaction items from before admission (the item can precede the ack), ignores `auto` ones, and settles on the terminal item, `noop`, deadline, host close or ACP cancel. Muse has no compaction cancel, so cancel only stops waiting. `compactCommand` (`src/host-commands.ts`) replies with the outcome and emits `compaction_update` only when `clientCapabilities.session.compaction` is set. No summary chunks: Muse items carry no summary text. Gate `supportsCompaction` (1.4.12+): `/compact` is unadvertised and sends nothing on older hosts and on exec.
- Tests: `src/tests/compaction-native.test.ts` (completed with and without the capability, failed, noop, refusal, cancel, argument rejection); `prompt-branches.test.ts` (old-host refusal, not advertised); `slash-commands.test.ts`; `src/tests/compaction-live.test.ts` (1.4.12 loopback refusal `compaction_unavailable` reported verbatim with no compaction updates, session continues; skips on 1.4.8).
