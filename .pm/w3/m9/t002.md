## Objective

A `/compact` command compacts the session through public `session/compact` where the host completes it, and reports refusals truthfully.

## Context

- Muse 1.1.1/1.2.1 rejected compaction with -32030 `compaction_unavailable` (`docs/capability-audit.md`); unknown slash names, including `/compact`, are currently prompt text and must stay so on hosts that refuse.
- Advertise only what t001 verified; keep explicit unavailability elsewhere.
- ACP SDK 1.8.0 (w3/m17/t001) standardizes compaction reporting but not triggering. Clients advertise `clientCapabilities.session.compaction`; agents then send `CompactionUpdate` (`in_progress`/`completed`/`failed`/`cancelled`, optional summary and error) and `CompactionSummaryChunk`, and must not send them otherwise. Source: Muse `compaction` items (`outcome`, `reason`, `trigger`).

## Steps

1. Add `/compact` as the trigger over `session/compact`. Report the outcome as standard `CompactionUpdate`/`CompactionSummaryChunk` to clients that advertise `session.compaction`, and as the command's reply text otherwise. Do not add a custom compaction extension.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Acceptance criteria

- [ ] On hosts where compaction completes, `/compact` compacts without a model turn from the adapter and reports the outcome; on refusing hosts it is not advertised or fails with the host reason; history and continuation stay correct afterwards.
- [ ] Clients advertising `session.compaction` receive the outcome as `CompactionUpdate` (plus `CompactionSummaryChunk` when Muse publishes a summary); other clients receive no compaction updates.
