# 002 — Keep new exec-backend sessions resumable through the SDK backend

Why: Sessions created through the exec backend on Muse 1.3.0-R3401.1+ get `:auto-review` and can never be loaded through the default SDK backend.

Triage 2026-10-06 on 1.4.3: `muse exec` commits the built-in `:auto-review` profile by default; `muse serve` refuses it (`resume_refused_class_c`). A `muse exec --permission-profile :ask-me` session read fine through serve, and `:unrestricted` committed correctly. Candidate: pass `--permission-profile` from `src/muse-exec.ts` (args near line 54) or the mode → `extraArgs` mapping (`src/acp-agent.ts:1855`, `src/modes.ts`), feature-detected via `muse exec --help`.

Open questions: the profile per ACP mode given existing `--disable-approval` / `--yolo` flags (respect DO_NOT_DO: no default bypass), and older hosts. Existing `:auto-review` sessions stay unreadable through serve; routing them to the exec backend is a larger, separate change.
