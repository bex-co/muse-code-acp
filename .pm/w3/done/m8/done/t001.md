## Objective

Evidence for which of goal/set, goal/edit, goal/pause, goal/resume, goal/clear (since SDK 1.3.0) the installed host completes, with exact request/response shapes.

## Context

- `src/slash-commands.ts` describes `/goal` as "persistent controls unavailable"; `docs/capability-audit.md` row "native goal mutation" says no method exists (audited at SDK 0.1.1); `session/goalChanged` is already folded into the `muse/goal` extension.
- Use the loopback provider and isolated directories; no paid tokens.
- Depends on w3/m7 so verification runs on Muse 1.4.6 with SDK 1.4.6.

## Steps

1. Probe each method through the public SDK connection and record outcomes, errors and resulting folded events/items.
2. Record which hosts/versions support each operation and any refusal kinds.

## Files

- Throwaway probe only

## Acceptance criteria

- [x] Per-method outcome table with host version recorded in the milestone validation evidence.

## Out of scope

- Implementing the surface (t002).

## Evidence

Muse 1.4.6, public SDK connection, loopback provider, no paid tokens:

| Method                        | Result                                                           |
| ----------------------------- | ---------------------------------------------------------------- |
| `goal/set` (idle)             | accepted with `turnId`; Muse runs goal turns; observed goal set  |
| `goal/edit`                   | accepted, no turn; objective replaced                            |
| `goal/pause` on a paused goal | `commandRejected` `invalid_goal_state`                           |
| `goal/resume`                 | accepted with `turnId`; turns run                                |
| `goal/clear`                  | accepted; goal null (within ~110 ms even while a goal turn runs) |
| `goal/edit` after clear       | `commandRejected` `missing_goal`                                 |
| `goal/set` blank              | `invalidParams`                                                  |
