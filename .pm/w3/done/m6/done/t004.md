## Draft upstream issue (awaiting user approval; not posted)

Target: `meta-models/muse-code-sdk` (no existing issue found for "escalate exec", "headless approval", "exec hangs" on 2026-10-09).

> **Title:** Headless `muse exec` waits forever when the approval reviewer escalates a tool call (1.4.4)
>
> **Summary.** In `muse exec` (default `:auto-review`, `--approval-mode on-request`, judge on), when the approval reviewer submits `submit_approval_assessment` with `outcome: "escalate"`, the run stops making progress: the last JSONL event is `task.lifecycle.proposed` (`task_kind: "tool.bash"`), nothing further is emitted on stdout or stderr, and the process never exits. Headless exec has no user to answer and publishes no approval request a caller could resolve, so the run hangs indefinitely. `muse trace inspect` on the session log reports `tool-call batch with 1 call(s) was not committed`.
>
> **Reproduction (no inference spend).** Muse 1.4.4-R5419.1, macOS arm64. Point Muse at a local OpenAI-Responses-compatible stub that (a) answers the main request with a `bash` call `printf x > marker.txt`, (b) answers reminder requests with `submit_reminder_decision` (`decision: "none"`), and (c) answers the approval reviewer with `submit_approval_assessment` `{ risk_level: "low", user_authorization: "high", outcome: "escalate", rationale: "…" }`. Run `muse exec --json --session-id <uuid> "write the marker"` with stdin closed.
>
> | Reviewer outcome | Result                                                    |
> | ---------------- | --------------------------------------------------------- |
> | `approve`        | tool runs, exec exits 0 in ~3 s                           |
> | `escalate`       | last event `task.lifecycle.proposed`; no exit after 180 s |
>
> **Expected.** In headless exec an escalation should resolve without a user: deny the call and return the denial to the model (as `--user-input-auto-resolve` does for user input), or end the run with a non-zero exit and a clear terminal reason. A flag such as an explicit headless escalation policy would also work.
>
> **Impact.** Any non-interactive caller (CI, ACP adapters) hangs until killed. `@bex-co/muse-code-acp` now stops such runs after a deadline and reports the reason.
