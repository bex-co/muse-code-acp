## Draft comment for #80 — not posted

Saved-session continuity is another reason to support the reviewer in `muse serve`. With Muse Code `1.4.4-R5419.1` and `@muse-code/sdk@1.4.4`, our ACP adapter's opt-in exec backend creates Default-mode sessions using Muse's default `:auto-review` profile. The SDK backend then cannot load or resume those sessions: the host refuses the saved profile because its automated reviewer is unavailable.

The recorded reproduction uses an isolated workspace/home/config/data directory and a local loopback provider, without paid model tokens:

1. Create a retained session with `muse exec --json --session-id <fresh-uuid>` using the normal Default-mode approval and sandbox settings.
2. Let the turn finish, retaining the session log, then attempt to read/load and resume the same session through the public SDK on `muse serve`.
3. The host returns `resume_refused_class_c`, with detail `permission profile ':auto-review' cannot be used: the automated reviewer is unavailable on this host`. SDK-created sessions remain resumable on this host.

Our repository records the refusal on 1.4.3 and the mode/profile comparison on 1.4.4: [1.4.3 evidence](https://github.com/bex-co/muse-code-acp/blob/1d0258485018c7f24c39a4171c7eba5d9586329e/.pm/w3/done/m2/done/t003.md), [1.4.4 comparison](https://github.com/bex-co/muse-code-acp/blob/1d0258485018c7f24c39a4171c7eba5d9586329e/.pm/w3/done/m4/done/t002.md), and [public SDK load-refusal handling](https://github.com/bex-co/muse-code-acp/blob/1d0258485018c7f24c39a4171c7eba5d9586329e/src/legacy-profile.ts).

Could reviewer support also make saved `:auto-review` sessions readable and resumable? Alternatively, a documented, explicit profile override when loading/resuming would let a client request a compatible posture with the user's consent. Today the profile composition is refused before the session loads, so setting the approval mode afterward cannot repair it. We keep Default mode's approval defaults, report the limitation, and steer users to SDK-created sessions for continuity.

The separate refused-write stall seen with our loopback harness remains unattributed and is not asserted as a host defect in this request.
