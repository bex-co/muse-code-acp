## Objective

The loopback stub answers requests that offer only `submit_reminder_decision` with a valid call, and the stall is either gone or shown to persist.

## Context

- Triage at `1d025848`: the provider falls back to plain text for reminder-only requests. `src/tests/loopback-provider.test.ts` asserts no function call for such a request; that expectation must change with the fix while preserving the scripted bash-call budget.
- The existing exec profile live test covers Read-only continuity only. A passing test there does not establish Default-mode refused-write completion.

## Steps

1. Teach `startLoopbackProvider` to reply with a `submit_reminder_decision` tool call when that is the only offered tool (shape from the request's tool schema). Update the unit contract to verify the decision call and that reminder replies do not spend the scripted main-agent bash call.
2. Rerun the t001 reproduction with the same host and Default-mode flags; record actual refusal and elapsed completion or capture deadline. If the turn completes, add a live test proving both that the write was refused (the artifact remains absent) and that the ACP prompt ends `end_turn`.
3. Run the full loopback suite to catch tests that relied on the old text reply.
