# 009 — Assess stricter TypeScript compiler flags

Why: `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` catch undefined-handling bugs that are common in protocol translation; counting hits decides whether adopting them is worth it.

Estimate: 1h. Source: 2026-10-15 `/pm-brainstorm` on code quality. `tsconfig.json` extends `@tsconfig/node22` (strict) without either flag.

- Count `tsc --noEmit` errors with each flag enabled and record the counts.
- Enable a flag only if its fixes are mechanical and behavior-preserving; otherwise record why not.
- Best done after w3/m18 to avoid conflicts with the `src/acp-agent.ts` split.

## Done (2026-10-27)

- `noUncheckedIndexedAccess`: **adopted**. 143 errors (47 production in 5 places, 96 tests), all mechanical: narrowing (`const [first] = matches`, `.at(-1)`, `atLeast` for the fork version check) or `!` on always-present regex groups and test indexes. No real bugs.
- `exactOptionalPropertyTypes`: **not adopted**. 63 errors (57 production), all "property set to undefined vs absent", which serialize identically to JSON; fixing them means about 30 `| undefined` additions or about 20 conditional spreads in core session/host code for no behavior gain.
- Unit 531/531; coverage green 3× after giving `model-discovery.test.ts` a 30 s discovery deadline (its 5 s default flaked under coverage load).
