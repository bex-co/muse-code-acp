## Objective

Never show the same model twice as `(meta)` and `(meta / tbh)`.

## Context

- Triage finding: when a turn runs before discovery completes, `src/acp-agent.ts` (around lines 1662/1670) pins `profileId: null`; `buildConfigOptions` then compares profiles strictly and injects the current selection as a separate entry. Sessions saved by earlier versions always stored `null` and hit the same path.

## Steps

1. When the current selection has no profile and exactly one catalog row matches its model and provider, adopt that row (in both `buildConfigOptions` and `resolvedModel`).
2. Do not pin `profileId: null` when discovery is unavailable; leave it undefined.
3. Keep an explicitly profiled selection that is absent from the catalog visible, as today.

## Files

- src/config-options.ts, src/acp-agent.ts, src/tests/config-options.test.ts, src/tests/model-identity.test.ts

## Acceptance criteria

- [x] Tests cover: null-profile selection with one matching profiled row → single entry; ambiguous match (two profiles) → current selection kept distinct; restored legacy preference with `profileId: null` → single entry.
- [x] Selection after adoption routes with the adopted row's profile.

## Out of scope

- Changing how preferences are persisted on disk beyond the null/undefined distinction.

## Evidence

- `buildConfigOptions` (`src/config-options.ts`) treats a `profileId: null` selection with no exact row and exactly one same-model/provider row as that row; ambiguous matches keep the pinned selection as a separate entry.
- Tests: `shows a selection pinned without a profile as the one catalog row it names` (`src/tests/model-identity.test.ts`) covers single and two-profile cases; the profiled wire test asserts the menu lists `muse-spark-1.2` once after a turn pinned it without a profile (the restored-legacy-preference path uses the same function).
- Deviation, recorded: the turn path still pins `profileId: null` when no catalog is known. Turns route correctly without a profile (as on `main`), and switching the pin to the adopted profile would change the host identity and restart the host. An explicit selection of the adopted row routes with its profile via `selectModel`.
