## Objective

Replace the hard-coded `muse-spark-1.2` default with a catalog-derived default where a catalog is available, without silently opting users into a contributor model.

## Context

- PR #10 commit `0b5c7b4` hard-codes `muse-spark-1.3`. Triage: the adapter always calls `session/setModel` with its default when settings name no model, so a host or gateway catalog without 1.3 fails the first turn ("Muse rejected the requested model/provider"), and exec `KNOWN_MODELS` is still 1.2-only.
- The catalog default on Muse 1.4.3 Meta accounts is `muse-spark-1.3-contributor`, whose description says content may be used for product improvement; do not inherit it silently (PR #10's rationale, which stays valid).
- Discovery at `session/new` has a short deadline; see w2/014 for slow host startup.

## Steps

1. When settings name no model and discovery is available: if the catalog default is a `-contributor` model and its non-contributor sibling is listed, use the sibling; otherwise use the catalog default.
2. When discovery is unavailable: keep `muse-spark-1.2` (the documented baseline), and keep exec `KNOWN_MODELS` consistent with it.
3. Settings and restored session selections still win.

## Files

- src/config-options.ts, src/acp-agent.ts, src/tests/config-options.test.ts, CHANGELOG.md

## Acceptance criteria

- [x] Tests cover: catalog default contributor with sibling → sibling; contributor without sibling → catalog default; no catalog → `muse-spark-1.2`; settings model → settings model.
- [x] No path sends `session/setModel` with a model absent from an available catalog unless the user or settings chose it.

## Out of scope

- Changing exec CLI defaults.

## Evidence

- `catalogDefaultModel` (`src/config-options.ts`) and `adoptCatalogDefault` / `builtInModel` (`src/acp-agent.ts`): new SDK sessions whose settings name no model follow the catalog default until a turn or model selection uses the model; contributor defaults yield to a listed non-contributor sibling; without a catalog the default stays `muse-spark-1.2` and exec `KNOWN_MODELS` is unchanged.
- Tests: `catalogDefaultModel` unit cases (sibling, no sibling, plain default, none, fallback) in `src/tests/config-options.test.ts`; wire test `follows the catalog default until a turn uses the built-in model` asserts the menu after `/models`, `session/setModel` with `muse-spark-1.3`/`tbh`, the cached catalog at a later `session/new`, and a settings model winning.
- Limitation: the catalog must be known before the first turn (`/models` or this agent's cache); the execution host's catalog arrives once a turn has started, after which the model no longer changes.
