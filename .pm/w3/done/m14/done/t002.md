## Objective

`/plugins` and `/hooks` list installed plugins and hooks; plugin install and marketplace changes run only on explicit user commands.

## Context

- Install and marketplace changes modify the user's Muse setup: never automatic, always an explicit command with the exact target echoed, and refused when the host reports `pluginMutationsDisabled`.
- Advertise only what t001 verified; keep explicit unavailability elsewhere.

## Steps

1. Implement the ACP surface (slash command and/or negotiated extension) over the verified methods.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Files

- src/
- src/tests/

## Acceptance criteria

- [x] Listing commands show host data; install/marketplace commands mutate only on explicit user input, surface host errors (`pluginNotFound`, `marketplaceAlreadyExists`, `pluginMutationsDisabled`) verbatim, and are covered by tests that never touch the real user configuration.

## Evidence

- `src/host-commands.ts`: `pluginListCommand`, `pluginInstallCommand(path)` (explicit command; echoes the exact path), `hookListCommand`; refusals as reply text.
- Parser: `/plugins`, `/plugins install <folder>`, `/hooks` (usage notices otherwise). Gated on Muse ≥ 1.4.7. Marketplace add/update/remove and `name@marketplace` installs are not offered (success unobserved).
- Tests: parser cases, fake-MSP flow (list, install, relative-path refusal, hooks), live in `native-commands-live.test.ts` with a temp-root plugin (2/2 on 1.4.7); the user's real configuration is never touched.
