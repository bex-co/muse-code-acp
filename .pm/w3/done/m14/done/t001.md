## Objective

Evidence for which of plugin/list, hook/list (1.4.4); plugin/install, plugin/marketplaceAdd|Remove|Update (1.4.6); plugin/changed (non-folded) the installed host completes, with exact request/response shapes.

## Context

- Install and marketplace changes modify the user's Muse setup: never automatic, always an explicit command with the exact target echoed, and refused when the host reports `pluginMutationsDisabled`.
- Use the loopback provider and isolated directories; no paid tokens.
- Depends on w3/m7 so verification runs on Muse 1.4.6 with SDK 1.4.6.

## Steps

1. Probe each method through the public SDK connection and record outcomes, errors and resulting folded events/items.
2. Record which hosts/versions support each operation and any refusal kinds.

## Files

- Throwaway probe only

## Acceptance criteria

- [x] Per-method outcome table with host version recorded in the milestone validation evidence.

## Out of scope

- Implementing the surface (t002).

## Evidence

Muse 1.4.7-R6101.1, isolated home, network blocked by a dead proxy, no paid tokens. A minimal valid native plugin needs `.muse-plugin/plugin.json` with `schemaVersion: 1`, `compat: {source: "native", manifestDir: ".muse-plugin"}` and object-valued `capabilities` arrays.

| Method                                                        | Result                                                                                                     |
| ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `plugin/list`, `hook/list` (fresh)                            | `{plugins: []}`, `{hooks: []}`                                                                             |
| `plugin/install` local path                                   | accepted, `{id, version, enabled: true, source: "nativeLocal"}`; listed; re-install idempotent             |
| `plugin/install` missing path                                 | `internal` "failed to read plugin store …"                                                                 |
| marketplace install / update / remove of an unconfigured name | `marketplaceNotFound`                                                                                      |
| `plugin/marketplaceAdd` local folder                          | refused until the catalog schema is satisfied (`version`, then `/install/transport`); success not observed |
