## Objective

`/skills` can enable, disable and import skills, and `/feedback` submits feedback to Muse.

## Context

- `/skills` currently lists skills only; feedback has no ACP surface. Feedback submission can attach session records and files: default to the minimum and require explicit user arguments for attachments.
- Advertise only what t001 verified; keep explicit unavailability elsewhere.

## Steps

1. Implement the ACP surface (slash command and/or negotiated extension) over the verified methods.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Files

- src/
- src/tests/

## Acceptance criteria

- [x] `/skills enable|disable|import` call the public methods and the listed state reflects the change; `/feedback <classification> <note>` submits with no files or session record unless explicitly requested and reports the host outcome (uploaded/recorded/disabled…).

## Evidence

- `src/host-commands.ts`: `recapCommand`, `skillActivationCommand` (scope from the skill's `skill/list` source), `skillImportCommand` (preview unless `--apply`), `feedbackCommand` (never files; session record only with `--with-session`); Muse refusals become reply text.
- Generic `hostCommand` hook in `spawnMuseSdkTurn` (recap moved onto it); `MuseSdkHost.call()` for session-scoped calls; the execution host requests the `feedback` capability.
- Parser: `/skills` alone still lists; `/skills enable|disable <skill>`, `/skills import claude|codex [--apply]`, `/feedback bug|bad|good|other <note> [--with-session]` (usage notices otherwise). Gated on Muse ≥ 1.4.7.
- Tests: parser cases, fake-MSP flow in `session-commands-native.test.ts`, live `native-commands-live.test.ts` (import preview/apply, disable/enable, offline feedback; 2/2 on 1.4.7).
