## Objective

The adapter compiles and behaves identically on `@agentclientprotocol/sdk` 1.8.0 for clients using the existing protocol surface.

## Context

- Pinned 1.3.0 in `package.json`. The types removed by 1.8.0 (`AuthEnvVar`, `AuthMethodEnvVar`, `ConnectMcp*`, `DisconnectMcp*`, `McpConnectionId`) have no `src/` references (checked 2026-10-15).
- Wire contracts are covered by `src/tests/acp-wire.test.ts` and the other `*-wire.test.ts` files.

## Steps

1. Read the SDK's release notes for 1.4.0–1.8.0 and the schema diff; note breaking or behavior-changing items.
2. Bump the exact pin and update the lockfile; check Node engine and `zod` peer compatibility.
3. Fix type errors without changing wire behavior; check initialize response, capability objects and stop reasons for newly required fields.
4. Run the wire tests and investigate any change in serialized output.

## Evidence

Bumped to 1.8.0 (exact). Release notes 1.4.0–1.8.0: elicitation APIs stabilized (1.4.0); incoming transport messages bounded (1.5.1); schema updates to v1.22–v1.25 and v2 alphas; v2-only changes otherwise.

Two type errors. (1) `src/auth.ts` advertised the API-key method as `type: "env_var"`, an UNSTABLE type 1.8.0 removed; my brainstorm check had grepped only for the removed type names, not the literal. It is now a standard agent method (no `type`), whose `authenticate` already only checks that `META_API_KEY` is set; `auth.test.ts` pins it. (2) A test-only `flatMap` typing fix in `file-change-live.test.ts`.

Behavior change found and handled: 1.5.1's 32 MiB incoming limit closes the transport, and the adapter exited 0 with no output (33 MiB message; 31 MiB is fine). `src/index.ts` now reports `MessageTooLargeError` on stderr and the log and exits 1; a wire test spawns the entrypoint and fails against the old code (exit 0). Schema diff: no newly required fields; MCP-over-ACP message shapes changed but the adapter does not tunnel MCP. Existing wire tests pass unmodified. `npm run check`, `build`, `test:unit` (510/510) and `test:pack-smoke` pass.
