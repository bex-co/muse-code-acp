## Objective

Task and workflow cards offer verified stop, background, pause and resume actions, and running tasks can be listed.

## Context

- The negotiated `muse/asyncTasks` extension and `_muse/task` currently offer only workflow `cancel` (`WORKFLOW_CANCEL_HOSTS`); generation-bound targets and stale-target rejection exist (`src/async-tasks.ts`).
- Advertise only what t001 verified; keep explicit unavailability elsewhere.

## Steps

1. Implement the ACP surface (slash command and/or negotiated extension) over the verified methods.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Files

- src/
- src/tests/

## Acceptance criteria

- [x] Each action is advertised only on hosts where it was verified against a real observed task/workflow, routes through `_muse/task` with the existing target validation, and the item terminal (not the command acceptance) is reported as the outcome; task listing is available where `task/list` exists.

## Evidence

- `taskActions` (`src/async-tasks.ts`) decides per-card actions: running unpaused workflow → cancel (verified hosts) + pause; paused workflow → none; foreground tool → background; backgrounded tool → stop. `parseTaskRequest` accepts `cancel|pause|background|stop`; `sendTaskControl` maps Muse refusals to `Muse rejected <method>: <reason>`.
- `MuseSdkHost.taskControls` gates pause/background/stop on `supportsTaskControls` (Muse ≥ 1.4.6) and cancel on `WORKFLOW_CANCEL_HOSTS` (now incl. 1.4.7, verified); `controlTask(target, action)` dispatches; `listTasks()` backs the new `/tasks` command.
- Tests: `taskActions` unit cases; live "backgrounds, lists and stops a running tool, and pauses a workflow" on 1.4.6 and 1.4.7 (2/2 + suite). Host moved to 1.4.7-R6101.1 mid-run: added to `WORKFLOW_CANCEL_HOSTS` and `FORK_CUT_LATEST_ONLY` after verification.
