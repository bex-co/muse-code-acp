## Objective

Evidence for which of task/background, task/stop, task/stopAll (1.3.0), task/list (1.4.6), workflow/pause (1.4.4), workflow/resume (1.4.6) the installed host completes, with exact request/response shapes.

## Context

- The negotiated `muse/asyncTasks` extension and `_muse/task` currently offer only workflow `cancel` (`WORKFLOW_CANCEL_HOSTS`); generation-bound targets and stale-target rejection exist (`src/async-tasks.ts`).
- Use the loopback provider and isolated directories; no paid tokens.
- Depends on w3/m7 so verification runs on Muse 1.4.6 with SDK 1.4.6.

## Steps

1. Probe each method through the public SDK connection and record outcomes, errors and resulting folded events/items.
2. Record which hosts/versions support each operation and any refusal kinds.

## Files

- Throwaway probe only

- [x] Per-method outcome table with host version recorded in the milestone validation evidence.

## Out of scope

- Implementing the surface (t002).

## Evidence

Muse 1.4.6, public SDK connection, loopback provider (approval mode `allowAll` for the probe), no paid tokens:

| Method                                         | Result                                                                    |
| ---------------------------------------------- | ------------------------------------------------------------------------- |
| `task/list`                                    | rows for running tasks, including foreground (`kind: tool`, `tool: bash`) |
| `task/background` on a running foreground bash | accepted; turn ends, tool keeps running (`backgroundInitiator: user`)     |
| `task/stop` on the backgrounded tool           | accepted; item `cancelled`                                                |
| `task/stopAll`                                 | accepted (only observed over an empty set)                                |
| `workflow/pause` on a running workflow         | accepted; item `paused: true`                                             |
| `workflow/resume`                              | accepted with a `turnId`; run never observed to unpause (model-mediated)  |
| `workflow/cancel` on a paused workflow         | `commandRejected` `missing_run`                                           |

Probe pitfalls recorded: workflow children need a supported effort (not `none`) and hold detection must target the child's own request.
