## Objective

`/recap` requests a native session recap, and `/rename` also sets Muse's own session name.

## Context

- `/rename` sets an adapter-owned title (`src/session-title.ts`); `session/nameChanged` is classified as ignored in `src/muse-view-events.ts`; recap is new in 1.4.6.
- Advertise only what t001 verified; keep explicit unavailability elsewhere.

## Steps

1. Implement the ACP surface (slash command and/or negotiated extension) over the verified methods.
2. Add deterministic tests (fake MSP) and a live test on the installed host, gated so CI's Muse 1.1.1 skips cleanly.

## Files

- src/
- src/tests/

## Acceptance criteria

- [x] `/recap` returns the host's recap (or its refusal) without an adapter-generated summary; `/rename` calls `session/rename` where available and the adapter title stays consistent with host name changes, with the ignore decision for `session/nameChanged` revisited.

## Evidence

- Host: notification tee settles recap waiters by `commandId` (early completions buffered); `requestRecap(isCancelled)` sends `recap/cancel` on ACP cancel or after 120 s; `renameNative(name)`; `isOpen`.
- SDK path: `recap` option streams the recap (or "Muse could not produce a recap (<outcome>: <reason>)"); `nativeName` applies a pending rename after acquire.
- Agent: `/recap` (sent alone) and `/rename` sync gated on `supportsSessionCommands` (Muse ≥ 1.4.7); rename applies immediately with an open host, else on the next turn; the adapter title (non-blank, validated) stays the display title. `session/nameChanged` remains ignored with the reason updated.
- Tests: `session-commands-native.test.ts` (fake MSP: recap, pending and immediate rename), parser cases, live `native-commands-live.test.ts` (2/2 on 1.4.7).
