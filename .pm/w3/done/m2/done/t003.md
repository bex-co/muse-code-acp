## Objective

Live tests reflect that `muse exec`-created `:auto-review` sessions are refused by the SDK backend on every host since 1.3.0-R3401.1.

## Context

- Triage on 1.4.3: `muse exec` commits the built-in `:auto-review` profile by default; `muse serve` refuses to read such sessions (`resume_refused_class_c`, detail "permission profile ':auto-review' cannot be used: the automated reviewer is unavailable on this host"). `isLegacyAutoReviewRefusal` (`src/legacy-profile.ts`) classifies it correctly and the adapter returns its actionable error. Normal SDK sessions resume fine. Not a user-facing regression.
- `src/tests/acp-real-host-helpers.ts` lists refusing builds (`LEGACY_PROFILE_LIMITED`, `LEGACY_PROFILE_READ_REFUSED`) and lacks `1.4.3-R5018.1`.
- Failing on `main`: `muse-sdk-live` "streams, resumes across processes…", `acp-restart-live` "binds via load" and "binds via resume".

## Steps

1. Replace the allow-list with: expect refusal from 1.3.0-R3401.1 onward unless a build is listed as fixed.
2. Run the three tests with `--no-file-parallelism`.

## Files

- src/tests/acp-real-host-helpers.ts

## Acceptance criteria

- [x] The three tests pass on 1.4.3 and still pass on the previously listed builds' expectations.

## Out of scope

- Adapter mitigation for new exec sessions (w3/002).

## Evidence

- Added `(1.4.3-R5018.1)` to `LEGACY_PROFILE_LIMITED` and `LEGACY_PROFILE_READ_REFUSED` in `src/tests/acp-real-host-helpers.ts`.
- Deviation, recorded: kept the enumerated lists instead of "expect refusal from 1.3.0-R3401.1 onward". The helper documents enumeration as deliberate so each new host is re-verified (that is how R3057.1 and R3401.1 were caught).
- `muse-sdk-live` resume and `acp-restart-live` load/resume pass on 1.4.3 (`--no-file-parallelism`).
