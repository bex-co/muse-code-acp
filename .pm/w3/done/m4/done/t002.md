## Objective

Evidence for choosing a `--permission-profile` per exec ACP mode.

## Context

- Exec modes (`src/modes.ts`): `default` (no flags), `readOnly`/`plan` (`--disable-write --disable-shell`), `bypassApprovals` (`--disable-approval`), `yolo` (`--yolo`). `muse exec` defaults to `:auto-review` with `--approval-judge on`.
- DO_NOT_DO: no fabricated permissions; no default `--yolo`/`--disable-sandbox`.

## Steps

1. With the loopback provider (no paid tokens) on the installed Muse, for each mode × candidate profile (`:auto-review` default, `:ask-me`, `:unrestricted`, any other built-in listed by the host), script a tool call that needs approval and record: tool outcome (ran / denied / judged), sandbox state, and whether `muse serve` can `session/read` and resume the session.
2. Record the table and a recommended mapping in the milestone validation evidence, with the safety trade-off per mode stated plainly.

## Files

- Throwaway probe only; no committed source changes.

## Evidence

Muse `1.4.4-R5419.1`, loopback provider, no paid tokens; scripted `bash` write needing approval, then SDK-backend `session/load` + prompt:

| Exec mode                                           | default (`:auto-review`)                                                                                                   | `:read-only`                       | `:ask-me`                   | `:unrestricted`                     |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | --------------------------- | ----------------------------------- |
| readOnly / plan (`--disable-write --disable-shell`) | no write; **load refused**                                                                                                 | no write; load ok                  | no write; load ok           | no write; load ok                   |
| bypassApprovals (`--disable-approval`)              | wrote; load ok                                                                                                             | exit 2: profile cannot be combined | exit 2                      | exit 2                              |
| yolo (`--yolo`)                                     | wrote; load ok                                                                                                             | exit 2                             | exit 2                      | exit 2                              |
| default (no flags)                                  | write refused by reviewer ("bash accepts only foreground read-only inspection commands"); exec did not finish within 180 s | did not finish within 60 s         | did not finish within 180 s | **wrote without approval**; load ok |

Recommendation: readOnly/plan → `:read-only` (loadable, no weaker than today: writes and shell are already disabled); bypassApprovals/yolo unchanged (already loadable; Muse refuses a profile with these flags); default unchanged (`:unrestricted` would remove approval, violating DO_NOT_DO; the other profiles are no more loadable-and-usable), documented as a limitation.

Separate finding: in this harness, default-mode exec did not finish after a refused write with every profile, today's default included. Not yet attributed (harness artifact vs real exec stall); needs its own investigation.
