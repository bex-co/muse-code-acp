## Objective

The exec backend never offers or forwards an effort `muse exec` rejects for the configured provider.

## Context

- `EFFORT_LEVELS` (`src/config-options.ts`) gates both backends; `muse exec` 1.4.x rejects `none` with `--provider meta` but `--help` still lists it.
- Provider: `src/muse-exec.ts` passes `--provider` (`meta` | `echo`); settings may name a provider.

## Steps

1. For the exec backend with a non-echo provider, omit `none` from the effort options and treat a settings `none` as unknown (default plus the existing log line).
2. Keep the SDK backend and the echo provider unchanged.

## Files

- src/config-options.ts, src/acp-agent.ts, src/tests/config-options.test.ts

## Acceptance criteria

- [x] Tests: exec + meta menu lacks `none`; exec + echo and SDK menus keep it; `set_config_option` `none` on exec + meta is rejected as invalid params.

## Out of scope

- Changing SDK-path effort mapping.

## Evidence

- `effortLevels(backend, provider)` (`src/config-options.ts`) omits `none` for the exec backend unless the provider is `echo`; `buildConfigOptions`, `applyConfigSelection` and `defaultSessionConfig` take the backend's list, and the agent logs a settings `none` it cannot carry (`src/acp-agent.ts` `defaultConfig`). SDK backend unchanged.
- Tests (`src/tests/config-options.test.ts`, `exec effort choices`): level lists per backend/provider; exec + meta session falls back to `high` with the log line, omits `none`, and rejects `set_config_option` `none` with -32602. 15/15 passed.
