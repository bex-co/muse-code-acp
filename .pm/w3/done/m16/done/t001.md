## Objective

When a test run declares the host capabilities it requires, a live suite skipped for a missing capability fails with a message naming it.

## Context

- `MUSE_CODE_ACP_REQUIRE_MUSE=1` only fails when no host is installed (top-level checks in `src/tests/*-live.test.ts`).
- Version gates include `supportsGoalControls`, `supportsSessionCommands` and `reviewerHost()`; grep `skipIf` in live suites and `src/tests/acp-real-host-helpers.ts` for the full list.
- Baseline legs must still skip capabilities their host genuinely lacks.

## Steps

1. Inventory every capability or version gate in the live suites and helpers.
2. Add one shared helper that decides skip, run or fail from a declared requirement (for example a `MUSE_CODE_ACP_REQUIRE_HOST_FEATURES` list of capability names, or a required minimum host version). Choose the simpler design and document it.
3. Route every gate through the helper.
4. Add a deterministic unit test for the helper.

## Files

- src/tests/acp-real-host-helpers.ts (or a new test helper)
- src/tests/*-live.test.ts
- A new or existing unit test file

## Acceptance criteria

- [x] Every live-suite capability gate goes through the helper; no ad-hoc version `skipIf` remains.
- [x] With no declaration, behavior equals today's.
- [x] Declaring a capability the host lacks fails the run with the capability named (recorded against the installed host).
- [x] The unit test covers skip, run and fail branches.

## Out of scope

- New live tests; CI workflow changes (t002).

## Evidence

Inventory: four capability gates, `exec-reviewer` (>=1.4.4, previously a hand-rolled version parse in `exec-profile-live`), `goal-controls`, `session-commands` and `task-controls` (previously an early `return`, so the test passed with no assertions on older hosts). Other version branches in the live suites assert host-specific behavior and still run. `hostSupports(name)` in `src/tests/helpers.ts` maps names to the existing predicates (`atLeast` is now exported from `src/muse-host.ts`); every gate uses it. `MUSE_CODE_ACP_REQUIRE_HOST_FEATURES` takes a comma-separated list or `all`. `src/tests/host-capabilities.test.ts` covers the run, skip and fail branches.

Real Muse 1.1.1-R2514.1 (public macOS arm64 artifact, manifest SHA-256 checked): without a declaration the goal-control and native-command suites skip (2 files, 2 tests skipped); with `MUSE_CODE_ACP_REQUIRE_HOST_FEATURES=all` both fail with `Muse host 1.1.1 lacks required capability "goal-controls"` / `"session-commands"`.
