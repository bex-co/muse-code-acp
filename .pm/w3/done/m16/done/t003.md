## Evidence

First leg runs: 67/68, all suites ran (no skips). The failure was `session-discovery-live`, an existing flake (CI run 35836348794 on 2026-09-23, and main run 38715606406 on 1.1.1 today, both "expected 51 to be 52"). Probing Muse 1.4.7 showed the cause: a session with no completed turn is discarded when its host closes, and other processes see such sessions only partially while it runs (a fresh host saw 8 of 10, then 3, then 0 as the writers closed). The test's 50 filler sessions had no turns. The fixture now creates only durable sessions (one turn, or forks of a session with one; Muse 1.1.1 refuses a 32nd loaded session per host with `runtime_busy`, hence two hosts), closes the writers, and polls the ACP listing until the index includes all 52. All pagination, provenance, title and load assertions are unchanged. File parallelism stays as before (the default script); both legs pass with it.

Two consecutive green runs on `4022109` (temporary branch `ci/w3-m16`, `workflow_dispatch`): [38720193800](https://github.com/bex-co/muse-code-acp/actions/runs/38720193800) and [38720625206](https://github.com/bex-co/muse-code-acp/actions/runs/38720625206). 1.4.7 leg: 21/21 files, 68/68 tests, none skipped, in both. 1.1.1 leg: 63 passed, 5 skipped (exactly the capability gates).
