## Objective

Each ACP schema type added since 1.3.0 has a recorded, evidence-backed decision: stability, negotiation, backing Muse public signal, and relation to existing `muse/*` extensions.

## Context

- The added types are listed in the milestone source.
- Candidate signals: turn lifecycle and pending approval/user input for `StateUpdate`; turn-failure categories (`src/turn-failure.ts`) for `ErrorStopReason`; workflow child sessions for `SubagentUpdate`; `session/compact` for `CompactionUpdate` (already assigned to w3/m9 by its 2026-10-15 triage; record it as deferred there); host warnings for `Notice`; cancellation for `SessionCancelCapabilities`.
- Existing extensions: `muse/asyncTasks`, `muse/goal`, progress and failure reporting (`docs/progress.md`, `docs/failures.md`).

## Steps

1. For each type, determine whether it is stable or unstable in the 1.8.0 schema and how a client negotiates it.
2. Identify the public Muse SDK/MSP signal that would back it, citing a test or live observation.
3. Compare it with the existing extension, if any.
4. Record a table in `docs/capability-audit.md` and the recommended w3/m19 scope in this task's evidence.
